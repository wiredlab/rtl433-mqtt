# rtl433-mqtt Service Deployment

This installs `rtl433-mqtt` as a boot-starting systemd service. The expected
flow is:

1. Clone the repository.
2. Edit `config/rtl433-mqtt.env`.
3. Run `sudo ./install.sh`.

## Fresh Install

Clone the repository on the Raspberry Pi:

```bash
git clone <repository-url> rtl433-mqtt
cd rtl433-mqtt
```

On `stippler`, keep the working clone at `/home/pi/rtl433-mqtt` unless local
operations choose another path. Upgrade the deployed source with:

```bash
cd /home/pi/rtl433-mqtt
git pull --ff-only
sudo ./install.sh
```

Before installing, confirm the compiled `rtl_433` has the expected native MQTT
features:

```bash
rtl_433 -V
rtl_433 -F help
```

The version should be newer than 25.12. The MQTT help should include
`availability`, `events`, `states`, `devices`, `base=<topic>`, env-based
credentials, and `mqtts://` options if TLS will be used.

Edit the service configuration before installing:

```bash
nano config/rtl433-mqtt.env
```

Important fields:

```sh
MQTT_HOST=localhost
MQTT_PORT=1883
MQTT_USERNAME=
MQTT_PASSWORD=
MQTT_TLS=0
MQTT_TLS_CA_CERT=
MQTT_TLS_CERT=
MQTT_TLS_KEY=

MQTT_TOPIC_PREFIX=rtl433
MQTT_BASE_TOPIC=
MQTT_RETAIN=0
MQTT_ENABLE_AVAILABILITY=1
MQTT_ENABLE_EVENTS=1
MQTT_ENABLE_STATES=1
MQTT_ENABLE_DEVICES=1

RECEIVER_FREQ=433.92M
RECEIVER_ID=
RTL433_OPTS=

RTL433_EVENT_LOG=/var/log/rtl433-mqtt/rtl433-events.jsonl
RTL433_LOG_JSONL=1
```

Install and start the service:

```bash
sudo ./install.sh
```

The installer:

- copies the repo into `/opt/rtl433-mqtt`
- copies `config/rtl433-mqtt.env` to `/etc/rtl433-mqtt/rtl433-mqtt.env`
- creates `/var/log/rtl433-mqtt`
- installs the systemd unit
- installs the logrotate config
- runs `systemctl enable --now rtl433-mqtt.service`

## Boot And Network Behavior

The systemd unit starts after local filesystems are ready and after the
`/var/log/rtl433-mqtt` mount path is available. It does not wait for
`network-online.target`, because local JSONL logging should start even when MQTT
is unavailable at boot.

MQTT publishing is handled by `rtl_433` directly. Current `rtl_433` builds have
native MQTT reconnect behavior, so the service wrapper does not pipe data
through `mosquitto_pub` and does not synthesize separate status messages.

Native availability is published under:

```text
${base}/availability
```

## Existing Config Protection

If `/etc/rtl433-mqtt/rtl433-mqtt.env` already exists, `sudo ./install.sh` keeps
the existing file and does not overwrite local MQTT settings.

To replace the installed config with the repo config:

```bash
sudo ./install.sh --force-config
```

## Updating The Application

To update code while preserving the deployed config:

```bash
cd /home/pi/rtl433-mqtt
git pull --ff-only
sudo ./install.sh
```

This updates `/opt/rtl433-mqtt`, the systemd unit, and the logrotate config. It
keeps `/etc/rtl433-mqtt/rtl433-mqtt.env` unless `--force-config` is supplied.

## Updating The Configuration

Edit the live config:

```bash
sudo nano /etc/rtl433-mqtt/rtl433-mqtt.env
sudo systemctl restart rtl433-mqtt.service
```

Use this path for normal MQTT broker, topic, TLS, receiver, and logging changes.

## Service Operations

Check status:

```bash
sudo systemctl status rtl433-mqtt.service
```

Follow service logs:

```bash
sudo journalctl -u rtl433-mqtt.service -f
```

Restart after editing `/etc/rtl433-mqtt/rtl433-mqtt.env`:

```bash
sudo systemctl restart rtl433-mqtt.service
```

Stop the service:

```bash
sudo systemctl stop rtl433-mqtt.service
```

## Local Logs

Decoded rtl_433 events are written as JSONL:

```text
/var/log/rtl433-mqtt/rtl433-events.jsonl
```

The installer places a logrotate config at:

```text
/etc/logrotate.d/rtl433-mqtt
```

Logs rotate daily, keep 30 date-suffixed compressed rotations, and use file
names such as `rtl433-events.jsonl_2026-07-03.gz`.

The logrotate config does not use `copytruncate`. It restarts
`rtl433-mqtt.service` after rotation so `rtl_433` opens a fresh active JSONL
file. This follows the same no-`copytruncate` policy as `s500-logger` while
accounting for `rtl_433` owning the file output.

## MQTT Payload And Topic Shape

The default base topic is:

```text
rtl433/<hostname>
```

Set `MQTT_BASE_TOPIC` to override the full base, or use `MQTT_TOPIC_PREFIX` and
`RECEIVER_ID` to build it.

The native `rtl_433` MQTT output publishes:

```text
${base}/availability
${base}/events
${base}/states
${base}/devices/
```

`events` carries decoded event JSON. `states` carries state summaries.
`devices/` contains nested device and sensor topics generated by `rtl_433`.

## Manual Verification

Print the command without starting the receiver:

```bash
RTL433_MQTT_PRINT_COMMAND=1 ./rtl433-mqtt
```

Subscribe to the configured base topic:

```bash
mosquitto_sub -h localhost -t 'rtl433/#' -v
```

Force log rotation for a deployed host:

```bash
sudo logrotate -f /etc/logrotate.d/rtl433-mqtt
```
